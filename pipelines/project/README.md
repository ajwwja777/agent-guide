# 项目启动与维护

入口与接管方式见[框架总览](../../README.md)。本流程由具体项目对话执行。新项目先确认基础，再发布基础，最后开展具体任务；用户只要求做到某一步时，就停在该步。

1. **了解现状**：检查已有目录、文档和源码，明确目标与工作位置，保留已有成果。
2. **确认基本框架与任务**：向用户展示简洁方案，说明项目目标、基本任务、本次范围，以及目录和模块如何组织、后续如何拓展，等用户确认。已明确确认的部分无需重复询问。
3. **搭建基础**：按确认方案建立必要目录、项目说明、配置和最小代码骨架，完成基础可用性检查；Git 与 GitHub 关系按 [GIT.md](GIT.md)处理。以稳定、可读、可拓展为目标，按实际需要组织文件。
4. **提交、推送并登记**：审阅基础文件，完成首次提交和 push，核验远端提交与本地一致，记录仓库链接、版本和完成状态，同步项目摘要与索引。推送受阻时先汇报并解决，不把本地建好等同于初始化完成。
5. **开展具体任务**：用户确认且基础已推送后，再进入盘点、复现、实验、训练等实际工作；若本次只要求初始化，完成后汇报即可。持续更新结果、经验和下一步。

本文件维护顺序与导航；Git 细节和默认设置统一在 GIT.md。新主题按需新增 MD 并在此链接，项目特例写在项目记录中。
