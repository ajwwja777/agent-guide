## 目录约定

在 A6000 新框架根下，`projects/<项目名>/` 保存实际项目，`agent-guide/projects/<项目名>/` 保存接管摘要，`scratch/<项目名>/` 保存临时文件。`<项目名>` 是占位符；新建前检查是否已存在。

其他机器的具体项目、数据和输出子目录由项目文档记录。Cobot 新根 `/home/agilex/jiaan/` 已确认；旧 `/media/agilex/Getea1/jiaan/`、`/home/agilex/cobot_magic/` 等仍有实际运行资产，只有对应迁移批次验收并切换后才更新实际使用位置。目标路径不等于已经部署。HPC 按当前任务授权使用。

以统一、可读、便于人工排查和溯源为原则，创建文件前先看已有结构，按用途归位。下面是按需采用的常见布局；已有项目沿用原结构并记清对应位置，无需为套用布局创建空目录。

| 内容 | 常见位置（相对实际项目目录） |
|---|---|
| 代码、可复用脚本和测试 | `src/`、`scripts/`、`tests/`，或原仓库对应目录 |
| 模型结构与训练参数 | `configs/`；初始模型随附配置与权重一起保留 |
| 数据 | `data/`，也可引用已有数据目录 |
| 初始／预训练权重 | `weights/base/`，也可引用已有模型缓存，记录来源与版本 |
| 每次实验的产物 | `outputs/<实验名>/`，集中保存 checkpoint、日志、实际配置和指标 |
| 项目说明和进展 | 项目 README 及已有记录文件，避免重复生成同用途文档 |

一次性排查脚本、下载包和可重新生成的测试中间文件放框架根下的 `scratch/<项目名>/`；需要区分时再按任务建子目录。长期工具放 `projects/agent-tools/`，其临时文件放 `scratch/agent-tools/`。有用的脚本和成果及时归入项目，确认不再依赖临时文件后再清理；scratch 不会自动清空。代码、配置和文档通常纳入 Git，数据、权重和大量输出通常通过忽略项排除。

A6000 保存主代码与项目记录，按需保留开发验证所需资产；HPC 保存训练所需代码、环境、数据、初始权重，并在当地实验目录写出 checkpoint 和日志；Cobot 保存部署代码、运行环境、选定模型及配套预处理文件，以及现场数据和评测记录。各机器只准备所需内容：首次训练补齐缺少的依赖和资产，后续同步变化的代码、配置与数据，已有同版本资产直接复用。训练后按需取回指标和选定模型；部署不必复制完整训练目录，传输后核对版本与完整性。

项目记录写清各机器的实际路径、代码版本（含影响运行的未提交修改）、数据与初始权重来源、实验配置、启动命令和产物位置。恢复训练保留所需优化器状态等 checkpoint 内容；部署保留推理所需文件，使用 adapter 时记清对应 base 模型。重要结果和排错结论简短留存，让下一次对话和人工检查能追溯到具体实验。

## 对话接管范式

笔记本统一入口是 `D:\Code\jiaan_workspace\AGENTS.md`，只负责通过 SSH 转接到本框架。项目对话目录可由用户自行建立，也可由框架对话代建；项目引导 MD 只需写“阅读笔记本统一入口”，再说明项目目标、来源（如 Git 地址）和本次做到哪一步。通用流程集中在本 README，再按需沿链接读取细节。

执行范围以用户本次要求为准；只要求建目录或写记录时，就做到这里。新项目默认先向用户确认基本框架和基本任务，再搭建简洁、稳定、可拓展的基础，完成首次提交与 push 并核验远端，然后开展具体任务；方案已明确确认的部分直接落实。具体顺序见[项目启动与维护](pipelines/project/README.md)。新建、恢复和迁移项目的对话按以下方式接管：

1. **按需读取**：从框架入口或用户指定文档出发，沿相关链接读取本项目记录与本次所需流程；缺少必要信息时再询问。
2. **确认现状**：明确项目、目标和工作位置，结合实际文件与 Git 状态核对已有进展，保留未提交修改。
3. **简要汇报**：说明对任务的理解、当前状态和下一步，等用户指示继续；用户已要求直接完成时，按授权继续。
4. **执行并留记录**：完成后汇报结果和修改文件，更新实际项目记录与框架摘要，注明来源、日期和下一步。

项目入口见[项目索引](projects/README.md)；流程按需读取：[项目启动与维护](pipelines/project/README.md)、[数采](pipelines/DATA.md)、[训练](pipelines/TRAINING.md)、[部署](pipelines/DEPLOYMENT.md)。新项目先检查是否已存在，再按本次任务范围执行项目流程，记录实际完成状态。

**agent-guide 本身也是一个项目**，工作目录就是本指南所在目录，以上层文档和 Git 状态承接进展；其职责是维护各项目对话共同更新的框架，接管方式与其他项目一致。框架对话为其他项目只创建笔记本对话目录及简短的引导性 `AGENTS.md`。A6000 项目目录、文档登记、Git 和 GitHub 操作由具体项目对话在本次任务范围内执行。

## 如何维护

agent-guide 用简短描述积累实际工作中的经验、错误和改进方法。按项目需要参考和调整，避免堆积繁杂规则、给项目增加不必要的限制。

具体项目参数、路径和进展放在项目文档中；通用流程放在对应 pipeline。项目启动与维护的新主题按需加入 `pipelines/project/`，并在[项目流程总览](pipelines/project/README.md)增加入口。

任意对话均可更新，无需指定管理对话审批。新增或修改 MD 中的流程时，先向用户展示拟写内容、涉及文件及简要原因，供用户学习和审核；用户确认后再写入。每次写完后，列出实际修改的 MD 文件的完整路径，并简要总结处理过程和结果。用户已明确批准的具体内容可直接落实。

新旧对话恢复工作时重新读取相关文档；具体任务的执行范围和是否逐步确认仍按当前对话要求。

框架维护对话在 `agent-guide/` 开启。技能复用时携带整个目录，迁移环境后更新框架位置与机器职责；当前尚未安装到技能发现目录。
